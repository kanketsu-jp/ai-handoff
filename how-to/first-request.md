# はじめての依頼 — PREFLIGHT から手渡しまで

> 前提: [`README.md`](../README.md) ／ 規則の正: [`SPEC.md`](../SPEC.md)

**題材**（ソフトウェアの話ではありません）:
社内の申請フローを作り直す人が、**実際に毎日申請している現場の人**に聞く。

```
作る人が欲しいもの   … どんな条件で誰に回るか（分岐が書ける粒度）
現場の人が持っているもの … 「こういうときは課長に聞く」という運用の実感
🚨 現場の人は「条件」「分岐」という言葉で聞かれても答えられない。**運用の言葉なら答えられる**
```

## 1. 🚨 いきなり `REQUEST.md` を書かない

**まず自分（依頼者）が、自分の LLM に聞かれる側になります。**
質問表は [`templates/PREFLIGHT.md`](../templates/PREFLIGHT.md)。

🚨 **8 問を上から読み上げるものではありません。** LLM は先に仕分けます。

| 仕分け | どうするか |
|---|---|
| 自分（LLM）が答えられる | 聞かない。**自分の答えを言って、違えば直してもらう** |
| この依頼に当てはまらない | 🚨 **聞かない。飛ばしたことだけ言う** |
| 依頼者しか知らない | 聞く。1 問ずつ |

例: 期限の無い依頼に「いつまでですか」と聞かない。**「期限は無い前提で書きます」と一言置く**だけ。

### いちばん効く 2 問

```
① すでに決まっていることは何か      → 聞き直してはいけない範囲
② 相手がすでに持っているものは何か  → 議事録・過去のやり取り・書きかけの案
```

🚨 **この 2 つを聞かずに書くと、相手が出た会議の結論を、ゼロから聞き直すファイルになります。**
「抽象的な質問になる」のは症状で、原因はここです。

## 2. 書く

雛形は [`templates/REQUEST.md`](../templates/REQUEST.md)。埋めるとき外せないもの:

- **本文は英語、会話は `lang:`**（読み手は LLM。日本語だとトークンが 1.5〜2 倍）
- **人物のことは `people` に短く。本文に散文で書かない**（ファイルは相手の手元に残る）
- 🚨 **「どの深さまで要るか」をトピックごとに書く**
  書かないと、相手の LLM は「相手が答えやすい深さ」で止まります
- 🚨 **相手が既に言っていることは、草案として見せて「合っていますか」と聞かせる**
  白紙で聞くと、相手は**知っておくと面白いこと**を答えます。それは使われません
- 🚨 **返してほしい JSON のスキーマは、こちらが出す**（相手の LLM に決めさせない）

### 🚨 制約を書くときは、必ず 1 行添える

費用・上限・取れない信号を伝えると、**相手は黙って要望を削ります。**
そして**何を望んでいたのかが分からなくなります。**

```
❌ 「◯◯は取れないので、△△で決めてください」
✅ 「いますぐ使えるのは △△ です。ただ、◯◯ で分けたいならそう言ってください。
    実現できるかは こちらの問題です」
```

### 🚨 「〜ではありません」と言わせない

ファイルの中の訂正は**相手の LLM 宛**です。人に向けて言うと、
**なぜ否定されているのかを考えさせます。** それはこちらの言い回しの経緯で、相手の仕事とは無関係です。

```
❌ 「これは追加の宿題ではありません。打ち合わせで割り当てられた…」
✅ 「これは打ち合わせで割り当てられた、この 2 つそのものです」
```

## 3. 渡す前に見直す

🚨 **`REQUEST.md` は回収できません。** 相手の LLM の文脈に入り、会話に残ります。
チェックリストは [`SPEC.md`](../SPEC.md) §8。とくに:

```
第三者の名前と事情 / 自分の側の判断・意図・金額 / 他案件の話 / 秘密（鍵・トークン・内部の名前）
✅ 自分以外の目で 1 回読む（別の LLM でよい）
```

## 4. 渡す

**本文に貼らず、ファイルを添付します。**貼ると、相手が LLM に貼り直す手数が増えます。
添える一文はこれだけです。

```
このファイルは私宛の依頼です。全部読んでから、書いてあるとおりに1つずつ質問を始めてください。
```

「全部読んでから」を入れるのは、**要約だけして終わるのを防ぐため**です。

## 5. よくある詰まり

| 症状 | 原因 | 直し方 |
|---|---|---|
| 質問が抽象的だと言われた | 相手が既に言っていることを使っていない | §1 の②。草案を見せて confirm させる |
| 浅い答えしか返らない | 「どの深さまで要るか」が無い | §2。決まらないと何が作れないかを書く |
| 相手が要望を小さくしてきた | 制約だけ書いた | §2。「やりたい形を先に言ってほしい」を添える |
| 「なぜ否定されるのか」と聞かれた | 訂正を人に向けて喋らせた | §2。肯定形にする |
| 全部埋まるまで返ってこない | 途中で返してよいと書いていない | 部分回答を先に求める |
