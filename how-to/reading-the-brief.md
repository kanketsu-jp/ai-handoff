# `BRIEF.md` が返ってきたら

> 前提: [`README.md`](../README.md) ／ 規則の正: [`SPEC.md`](../SPEC.md) §5・§8-4

## 1. 🚨 最初に見るのは、埋まっている項目ではありません

```
① unconfirmed（分からなかったもの）
② 「要確認」（本人では決められなかったもの）
```

**次の往復は、この 2 つだけです。** 埋まっている項目を読み直す必要はありません。

🚨 **`unconfirmed` は失敗ではなく回答です。** 自分で埋めないでください。
**空欄より、埋められた推測のほうが害があります**——推測は回答と見分けが付かず、
実装まで進んでから食い違いが出ます。

## 2. 🚨 `note` だけあって値が無いものは「未回答」

備考は「選んだうえでの条件・懸念」であって、答えではありません。
**議論したい／確認したい と書かれていたら、それは決定ではありません。**

## 3. 引用と、成果物を分けて読む

```
🟢 引用（>）  … 本人の言葉のまま。**翻訳も要約もされていないこと**が条件
🚨 成果物     … 依頼側が使える粒度に翻訳されたもの
```

**要約された引用は、判断材料にしないでください。** 引用は証拠で、
成果物はその翻訳です。**証拠が加工されていたら、翻訳の正しさを検算できません。**

## 4. `## 0. Environment` を読む

相手の LLM が**できなかったこと**と、**代わりにやったこと**が書いてあります。

```
例: ファイルを書けなかったので、チャットに全文を貼った
    外部ツールに接続できなかったので、データ登録はしていない
```

ここが空なら、**想定どおりの形で返ってきた**ということです。
**黙って別の手段に切り替えられていないか**を、ここで確かめます。

## 5. 「誰が決めたか」を見る

| 項目 | 回答 | 決めた人 | 状態 |
|---|---|---|---|
| … | … | 本人 | 確定 |
| … | — | **要確認（別の担当）** | 保留 |

窓口の人と決める人が違うことがあります。**保留の行だけ、直接聞きに行けます。**

## 6. 次の往復を作る

**新しい `REQUEST.md` を全部書き直さないでください。**
`unconfirmed` と「要確認」だけを持った、短いものを出します。

🚨 **そのときも PREFLIGHT を通します。** 1 往復目で分かったことが、
「すでに決まっていること」に増えているからです。

## 7. 途中版で構いません

```
## 進捗
- 回答済み: 3 / 6 項目
- 未着手: ［項目名］
- この BRIEF は **途中版** です
```

**3 項目だけ埋まっていても動けます。** 動けなくなるのは、
**どれが埋まっていてどれが埋まっていないか分からないとき**だけです。
